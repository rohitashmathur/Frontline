# V11 Human Playtest Checklist

Status: prepared, not executed. Automated simulations and generated screenshots are not human feedback.

Use a small first group, including a Hindi reader and an Indonesian reader if available. Install the test APK over an existing prototype when assessing migration; do not uninstall first. Ask permission before enabling the local playtest log. Export is manual and stays under the tester's control.

## First Session

1. Ask the tester to start a campaign battle without instructions. Observe whether they discover the primary action, deployment amounts and touch interaction.
2. After a defeat, ask what ended the attempt and what they would change. Do not lead with the explanation yourself.
3. Ask them to play Home Guard actively, then Province Guard. Record reinforcement, interception and counterattack attempts, not only completion.
4. Ask them to find Settings and Daily Mission. Note mistaken taps, hesitation or difficulty returning to the menu.
5. Ask them to switch to a language they can read, return to the same saved battle, then close/reopen the app. Ask whether translated instructions and failure reasons make sense.
6. Ask them to explain a Hold King and Troop Budget objective in their own words. Check whether they understand that friendly reinforcements consume budget and an excessive release still loses.
7. Ask whether they would replay, why, and what felt repetitive. Record the answer verbatim separately from your interpretation.

## Experimental Run

Play one five-battle Run, using the retry if needed. Record actual minutes, battles cleared, perk choices and whether the player can explain each effect. Ask whether the council creates a meaningful decision and whether they would start another Run. The 10-15 minute target is a hypothesis, not an established duration.

## Experimental Logistics

Compare a routed map with a similar Classic map. Ask the player to reinforce across friendly connected territory, attempt an impossible route and explain an interrupted convoy. Record confusion and attempted actions, completion/loss/timeout and actual duration. Ask whether routing improves decisions and enjoyment, rather than assuming more complexity is better.

## Session Record

| Field | Record |
| --- | --- |
| Build and device | Version, Android/device, screen size, language |
| Consent | Log enabled only with permission; export location if shared |
| Scenario | Mode/map/mission, visible difficulty, seed if available |
| Understanding | Player's own objective and defeat explanation |
| Actions | Intended action, actual command, confusion/mistaps |
| Outcome | Win, loss or timeout, elapsed duration, retries |
| Replay | Stated willingness and reason |
| Language | Unclear wording, clipping, glyphs, naturalness |
| Notes | Observation versus tester quotation kept distinct |

Do not expand rollout or declare human balance, linguistic quality or enjoyment validated until these sessions are actually run and reviewed. Experimental features can remain available in the review build while this evidence is pending.
